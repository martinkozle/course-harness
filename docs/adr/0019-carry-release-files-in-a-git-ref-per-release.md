# Carry Release files in a Git ref per Release

A Course Release's template and Artifact bytes (`inputs/template.pptx`, `artifacts/<id>.pptx`) live in Course Harness's local Release data, outside the Course Workspace, so a Git remote could not serve them to the Classroom. When a Release is published, Course Harness also writes, with Git plumbing only, a parentless commit whose tree holds exactly those files and points `refs/course-harness/release-files/<slug>` at it; the commit is derived only from the manifest and the bytes, so writing it again yields the same commit. Pushing sends the `main` branch, the `course-release/*` tags and these refs, and first backfills the ref of any older Release from local Release data. The working tree and the Course branch never contain the binaries, and ADR 0009 still holds: the manifest's sizes and checksums are authoritative, so a reader checks every blob's size before reading it and its SHA-256 after, and refuses a missing, extra or changed file. We chose a ref per Release over committing binaries to the branch (which would bloat every clone of the Course history and blur canonical state with generated files), Git LFS (an extra server-side service and client dependency), and release assets on a forge (not portable across hosts and not readable from a plain mirror). The cost is refs that a plain `git clone` does not fetch; the Classroom's `git clone --mirror` does.
