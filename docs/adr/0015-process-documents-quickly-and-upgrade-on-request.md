# Process documents quickly by default and upgrade on request

Every PDF, PowerPoint, Word, and HTML Resource is first converted by a Document Processor that is installed by default and runs no models: Docling Slim, with its native PDF pipeline. A plain install no longer needs PyTorch, model weights, or a download prompt before a PDF can be uploaded. Full Docling, which adds layout, table, and OCR models, moves to the optional `course-harness[docling]` extra. Course Harness never installs it, or any other package, itself. It shows the command to run instead. Packages licensed under the AGPL or GPL, such as PyMuPDF, are not dependencies, even though PyMuPDF gave the best CPU-only PDF result we measured ([research](../research/lightweight-document-processing-alternatives.md)).

The native PDF pipeline has no reading order, headings, tables, or OCR. So each conversion runs a Processing Quality Check for missing text, large images, and garbled characters. The check also flags image-heavy slides. A Resource that fails the check stays usable, and the Course Author is offered a better Document Processor: full Docling when installed, or a hosted one. The hosted options are LlamaParse, Mistral OCR, or a Model Preset that can read PDFs. The Course Author chooses one installation-wide default processor for these suggestions. They may opt in to applying it automatically. Each document can still be reprocessed with any available processor. A hosted Document Processor gets a document only after the Course Author consents to send documents to that vendor, once per vendor per installation. Its API key is a Processor Key and lives in installation credential storage, never in a Course Workspace. Every Resource shows which Document Processor produced its Derived Representation and whether it was sent off the device.

Reprocessing replaces the Derived Representation in place, unless a Source already pins the representation being replaced. Citations name line coordinates in that representation. So a pinned representation is kept beside the new one, and that Source keeps resolving to it. A representation nobody has admitted is discarded, because no Course can depend on it. A Source records which Document Processor produced its representation, and the Library registry records, per Resource, which representations Sources have pinned. Another Course Workspace that shares the Library therefore cannot lose one either.

This refines ADR 0007. A hosted Document Processor is not reproducible: running it again costs money and may not give the same lines. Its output is therefore also kept in the durable Library data directory. Clearing the processing cache restores that output from there instead of calling the vendor again, so deleting the cache still cannot invalidate a Course.
