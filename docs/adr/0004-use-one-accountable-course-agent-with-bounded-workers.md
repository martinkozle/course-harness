# Use one accountable course agent and defer bounded workers

Keep one persistent Course Agent responsible for the conversation and all typed Course mutations. Defer model-powered Worker Agents until after the first product demo: their parallel research and drafting would demonstrate multi-agent orchestration, but they add cancellation, reconciliation, provider-cost, observability, and failure-handling complexity without strengthening the demo's core Course-authoring journey. If introduced later, a Worker Agent receives an explicit task, bounded context and read-only tools, execution limits, and an expected structured result; it is not a name for FastAPI background work such as rendering or cleanup.
