# Offer detected credentials and delegate AWS credentials to the SDK

Course Harness reports the standard provider credentials it can see (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `OPENROUTER_API_KEY`, `AWS_BEARER_TOKEN_BEDROCK`, AWS session variables, and the profile names in the shared AWS configuration files) as Detected Credentials. It never uses one until the Course Author adds it with one click. Exa is seeded as a default Connector because it is keyless and free. Model credentials bill someone's account, so they are only offered, and every Provider Account keeps a visible origin. An added API key is copied into credential storage like any other key. AWS credentials are never copied. An AWS profile account stores only the profile name and region, and botocore resolves (and refreshes) SSO, role, and static credentials on every use. An AWS session account reads the session variables of the process on every use, because short-lived credentials from tools such as awsume would go stale in storage.

This is a deliberate exception to the rule that provider clients ignore ambient environment configuration. Bedrock traffic goes through botocore, which honours the standard AWS SDK proxy and CA bundle settings that AWS users depend on. Course Harness still pins each client's signature version, so an ambient `AWS_BEARER_TOKEN_BEDROCK` cannot replace SigV4 credentials, and it disables configured endpoint overrides such as `AWS_ENDPOINT_URL`.

Bedrock caches only at explicit cache points, so Course Harness requests them for instructions, tool definitions, and messages whenever the model ID shows the model family supports caching. When the ID cannot show it, as with an application inference profile ARN, the Course Author answers once when saving the Model Preset. Anthropic and OpenRouter models get the equivalent cache settings. OpenAI caches automatically.
