# Unstructured document parsing options

Researched 2026-09-20 from vendor documentation and source. Docling was selected as the local default for the initial implementation; hosted parsing remains an option for later evaluation. Prices and limits can change.

## What the vendors document

| Option | Input and OCR | Operation and privacy | Source location and cost |
| --- | --- | --- | --- |
| **Docling** | PDF, DOCX, PPTX, images and many other formats. PDF and image OCR can use Tesseract, RapidOCR, EasyOCR, and other engines. [Formats](https://docling-project.github.io/docling/usage/supported_formats/), [installation and OCR engines](https://docling-project.github.io/docling/getting_started/installation/). | Runs locally and can run fully offline after obtaining PDF model weights and any OCR model assets. DOCX/PPTX parsing does not need Docling model weights. Its Python package uses PyTorch for the models, with a documented CPU-only installation path. [FAQ](https://docling-project.github.io/docling/faq/), [installation](https://docling-project.github.io/docling/getting_started/installation/). | `DoclingDocument` carries document hierarchy, item provenance, and bounding boxes where available; Markdown export alone loses some of that structure. [Document model](https://docling-project.github.io/docling/concepts/docling_document/), [formats and outputs](https://docling-project.github.io/docling/usage/supported_formats/). | **Docling Slim configuration** | Same codebase with opt-in format, OCR, and model extras. The README estimates about 50 MB of **base dependencies**, not the installed size with PDF, Office and OCR extras or model assets. [Slim README](https://github.com/docling-project/docling/blob/main/packages/docling-slim/README.md), [packaging reference](https://github.com/docling-project/docling/blob/main/docling/.agents/skills/docling/references/slim-packaging.md). | PDF-to-Markdown/JSON without ML is documented, but quality relative to full Docling on complex layouts is unmeasured for this project. [README](https://github.com/run-llama/liteparse), [PyPI release files](https://pypi.org/project/liteparse/2.11.1/). | JSON contains spatial text and bounding boxes; maintainers explicitly position cloud LlamaParse as stronger for dense tables, columns, charts, handwriting and scans. [Privacy](https://developers.llamaindex.ai/llamaparse/general/enterprise-readiness/data-privacy-security/). | `expand=markdown,items,metadata` exposes per-page text and structured content; metadata includes speaker notes, and granular bounding boxes are documented separately. ## Additional hosted parsers and free allowances

Checked against provider documentation and pricing on 2026-09-20. These are **bring-your-own-account** options; an application-wide free tier cannot be shared among Course Authors without the application owner holding the account, paying overages, and taking custody of uploaded files. Page allowances and prices below are vendor terms, not parser-quality measurements.

| Provider | Document and result fit | Free allowance and paid cost | Data handling and practical limit |
| --- | --- | --- | --- |
| **Mistral OCR 4.1** | The [OCR processor](https://docs.mistral.ai/studio/document-processing/basic_ocr) documents PDF, PPTX and DOCX as `document_url` inputs. For PDFs it explicitly documents public URL, base64 payload, or private file upload. It returns Markdown per page, tables, images, and, in OCR 4+, paragraph blocks with bounding boxes. Test Office files directly: Mistral's [file-upload limitations](https://docs.mistral.ai/resources/known-limitations) list only PDF/images as OCR upload formats, even though the processor page lists PPTX/DOCX as `document_url` inputs. | Mistral's [Free plan](https://mistral.ai/pricing/) lists **$10/month in API credits**, and [Free-mode API keys](https://docs.mistral.ai/getting-started/quickstarts/studio/activate-and-generate-api-key) need no credit card. At the current [OCR 4.1 price](https://mistral.ai/pricing/api/) of $4/1,000 pages ($5/1,000 for Document AI), the credit has substantial potential for light use, subject to per-account OCR/rate limits and eligibility of the credits for OCR. Verify that entitlement in a real free account before treating it as a production quota. | [Privacy policy](https://legal.mistral.ai/terms/privacy-policy/) says API input/output may be retained for 30 days for abuse monitoring. Uploaded files are [retained for 30 days unless deleted earlier](https://docs.mistral.ai/resources/known-limitations). [Zero data retention](https://docs.mistral.ai/admin/monitor-comply/zero-data-retention) is for eligible paid stateless OCR calls, but excludes the Files API. Base64 avoids the separate Files API storage path, although the ordinary OCR request still follows the API retention policy. |
| **Google Document AI** | Its [layout parser](https://docs.cloud.google.com/document-ai/docs/layout-parse-chunk) supports PDF, DOCX and PPTX (including headings/tables/lists); Office support is **only** through layout parsing, not the cheaper OCR processor. PDF online requests are limited to 20 MB and 15 pages for this parser; larger work uses batch. The [Document response](https://docs.cloud.google.com/document-ai/docs/reference/rest/v1/Document) carries page numbers and bounding polygons. | The [pricing page](https://cloud.google.com/products/document-ai/pricing) lists **1,000 free pages/month for Enterprise Document OCR**, then $1.50/1,000 pages. That free OCR allowance does **not** cover Office parsing or the layout parser, listed at $10/1,000 pages. Google Cloud new-account trial credits are separate from this recurring OCR allowance. | [Security documentation](https://docs.cloud.google.com/document-ai/docs/security) says customer documents are not used for model training; synchronous requests are processed in memory, while batch inputs are briefly stored with a one-day failsafe TTL. Needs a Google Cloud project, billing setup and credentials. |
| **Azure AI Document Intelligence** | The [Read and Layout models](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/model-overview?view=doc-intel-4.0.0) accept PDF, DOCX and PPTX; [layout results](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/prebuilt/layout?view=doc-intel-4.0.0) include page and polygon locations. Its docs say embedded or linked **images in Office files are not analyzed**, so image-heavy slides need a separate rendering/OCR path. | The [F0 pricing tier](https://azure.microsoft.com/en-ca/pricing/details/document-intelligence/) provides **500 pages/month ongoing**, but [service limits](https://learn.microsoft.com/en-us/azure/ai-services/document-intelligence/service-limits?view=doc-intel-4.0.0) cap F0 at **4 MB/file and the first 2 pages/slides per request**. This makes it useful for evaluation, not normal lecture decks or PDFs. Paid S0 pricing is region/model dependent and should be checked in the Azure calculator. | Microsoft says [input and results are held for 24 hours](https://learn.microsoft.com/en-us/azure/foundry/responsible-ai/document-intelligence/data-privacy-security), then deleted, with earlier deletion through the Delete Analyze Result API. Requires an Azure resource and key. |
| **Amazon Textract** | [Supported inputs](https://docs.aws.amazon.com/textract/latest/dg/limits-document.html) are PDF, TIFF, JPEG and PNG, **not PPTX or DOCX**. Synchronous PDF processing is one page/10 MB; larger PDFs require asynchronous processing through S3. [Block geometry](https://docs.aws.amazon.com/textract/latest/dg/text-location.html) provides page coordinates. | AWS states the [free tier lasts three months](https://aws.amazon.com/textract/faqs/) for new customers: up to 1,000 text-detection pages/month or 100 pages/month with forms/tables/layout. This is a **time-limited trial**, not an ongoing free allowance. Paid pricing varies by API feature and region. | Its [FAQ](https://aws.amazon.com/textract/faqs/) says AWS may store/use submitted content to maintain and improve Textract and related ML services. A production workflow would need AWS credentials and, for most course PDFs, S3. |

**Shortlist inference:** Mistral deserves a corpus comparison alongside LlamaParse because of its page-structured output, low published page price, and current monthly Free-plan API credits. Verify OCR-credit applicability and private PPTX/DOCX upload before promising one provider for every unstructured format. Google is a strong layout-parser comparator, but its 1,000-page recurring free quota belongs to the simpler PDF/image OCR processor. Azure's two-page F0 cap and Textract's PDF-only input plus three-month trial make them weaker default candidates. Any hosted option needs a clear per-upload disclosure, a key/credential flow, and a local Docling fallback for offline or private material.

## Implementation check in Course Harness

Full Docling 2.129 with CPU-only PyTorch installed and imported under the pinned Python 3.14 Nix shell. The local model prefetch completed and occupied about 730 MB in a test cache; the full development virtual environment occupied about 1.7 GB. These are measurements on this Linux machine, not guarantees across releases or platforms. PDF upload now requests model-download consent, and the runtime cache stores both extracted Markdown and structured Docling JSON. A real PDF and PPTX conversion, plus PDF consent/indexing tests, passed. A representative corpus and memory/time benchmarks remain necessary.

## Fit with Course Harness (architectural inference)

The repository's current upload limit is 100 MiB. Parsing now runs in a worker thread during the upload request, and indexed artifacts are `extracted.md` plus full-text-search line coordinates; Docling JSON is preserved in the runtime cache. Very large/scanned documents still need bounded background work, progress and failure states, and better page/slide provenance in Source citations. The vendor claims above do not establish quality on our own lecture slides, scans, tables, or multilingual documents; a representative corpus comparison is needed.

Docling and LiteParse are directly documented for local, offline processing without a user-supplied API key. Full Docling would make the default install and CPU processing heavier, especially for PDFs. Slim may lower installation cost, but its no-ML configuration needs an accuracy check before calling it a sophisticated parser. LiteParse's native focus is PDF; Office conversion adds LibreOffice. Keeping a lightweight fast path for simple documents and using Docling for complex or scanned ones is a possible design, but it adds routing and quality-detection logic. A hosted LlamaParse option reduces local compute and may handle harder scans/charts, but requires a key, internet access, explicit consent to send course files off device, cost controls, and a local fallback. Tavily is useful for web sources, not a substitute for uploaded-file parsing under its documented Extract/Crawl API.

## Limits and unresolved checks

- Docling explicitly says Python 3.14 is supported beginning with version 2.59.0. Full Docling 2.129 now imports and converts Office documents in this repo's Python 3.14/Nix environment, but a representative corpus run is still needed. [FAQ](https://docling-project.github.io/docling/faq/).
- Docling documents a CPU-only PyTorch installation route and model weight downloads for PDFs, but these sources do not provide a reliable **total installed size, peak RAM/CPU, or first-run download size** for our chosen OCR engine and platform. Measure those in a reproducible prototype; avoid promising a specific footprint. [Installation](https://docling-project.github.io/docling/getting_started/installation/), [FAQ](https://docling-project.github.io/docling/faq/).
- Docling's offline mode requires model artifacts to be present beforehand. A first run without preloaded weights may fetch from Hugging Face; whether a packaged release can avoid a surprise download depends on deployment design. [FAQ](https://docling-project.github.io/docling/faq/).
- LlamaParse platform-wide upload maximum is 512 MB, while Parse caps image extraction/OCR to the 35 largest images per page and text extraction to 64 KB per page. These limits are above or orthogonal to our 100 MiB upload cap, but matter for unusual documents. [Limitations](https://developers.llamaindex.ai/llamaparse/general/limitations/).
- The documented LlamaParse v2 `Fast` tier returns spatial text/text only, not Markdown. For structured ingestion, compare Cost-effective and Agentic results; do not assume the cheapest tier meets table/reading-order needs. [Overview](https://developers.llamaindex.ai/llamaparse/parse/), [tiers](https://developers.llamaindex.ai/llamaparse/parse/guides/tiers/).
- OCR and source-location fidelity for **embedded raster images inside PPTX/DOCX**, and actual speaker-note coverage in PPTX, need direct corpus testing for both Docling and LlamaParse; a metadata field for notes or general format support does not prove those specific behaviors.

## Suggested follow-up evaluation

Run the same set through Docling full (CPU), Docling Slim with PDF/Office/RapidOCR extras, LiteParse, Mistral OCR, and LlamaParse Cost-effective/Agentic: born-digital PDF with two columns, scanned PDF, mixed text/image PDF, table-heavy PDF, PPTX with text plus screenshots and notes, DOCX with tables, and a multilingual scan. Score missing text, reading order, table integrity, page/slide attribution, processing time, peak RAM, installation/download size, and failure behavior. Use those measurements to decide whether a hosted option is valuable as an optional route for difficult files.
